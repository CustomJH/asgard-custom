# Freyja 2 — second visual delivery engine

The complete engine lives under `engine/` (relative to this skill's directory) and is followed wholesale. It is self-contained: vanilla node scripts (node >= 22.12), no package installs, no API keys.

1. Load `engine/SKILL.md` and follow it exactly — its Setup (run `node engine/scripts/context.mjs` once per session from the project root), its routing table of 23 commands and playbooks under `engine/reference/`, its craft floor, and its detector directives. That file is this engine's single design authority.
2. Path resolution: any `{{scripts_path}}`-style or `scripts/...` reference in engine documents resolves under `engine/scripts/`. Run scripts with `node`. Never run any network installer; everything needed is vendored here.
3. Detector and hooks: hook manifests are vendored under `engine/hooks/` as templates only — see `engine/hooks/README.md`. Asgard does not auto-install host hooks; replicate their effect by running `node engine/scripts/hook.mjs` after UI file edits and once before finishing, whenever working inside a project directory. Findings are acted on, not summarized away. The detector's static-HTML engine is self-contained (`engine/scripts/detector/vendor/`), so it needs no `npm install`; it does need node >= 22, and `asgard doctor` reports both.
4. Subagent roles live under `engine/agents/`. When a playbook asks for one and the host exposes a Task/Agent tool, spawn a general agent primed with that file's contents; otherwise substitute a disclosed in-thread pass.
5. Motion architecture invariant (Asgard addition, benchmark-proven): content paints first, choreography is additive. Never gate the hero or primary content's first paint behind an entrance sequence — base states stay visible without JS and without animation classes; staged openings that delay first paint are reserved for explicit user requests.
6. Artifact vault: the engine writes every project artifact it persists (design sidecar, critique snapshots, live journals, hook caches, surface briefs) under `.asgard/.vanadis/engine2/` — Fólkvangr, Freyja's field, inside the `.asgard/` directory `asgard init` creates. Asgard already keeps `.asgard/` out of git, so the vault needs no ignore entry of its own and must never add one. When a judging run ends, clear the run-scoped half with `node engine/scripts/vault.mjs sweep`; when the work is delivered, `node engine/scripts/vault.mjs purge` removes the vault outright. Never write engine state outside it, and never offer to commit it.
7. Asgard-wide invariants apply unchanged: user-facing surfaces follow Asgard's language and emoji conventions, accessibility floors (contrast, keyboard focus, prefers-reduced-motion) are never lifted, and evidence-first reporting is unchanged.
