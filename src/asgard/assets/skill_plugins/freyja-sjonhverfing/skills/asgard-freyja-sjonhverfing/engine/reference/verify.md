# 확인 — 소스로는 판정할 수 없는 것

`depth_gate.mjs` 는 소스에서 확정되는 열 가지를 판정한다. 아래 다섯은 렌더된 화면이 있어야 알 수 있고, 게이트가 `unjudged` 로 내보낸다. **항목 이름을 그대로 적어 보고한다. 침묵은 통과가 아니라 미확인이다.**

## M1 · 글자가 선명한가

정지 상태에서 카드의 본문을 실제로 읽는다. 스크린샷이 아니라 화면에서.

- 흐리면 변환이 남아 있는 것이다. 애니메이션 종료 후 `transform` 과 `will-change` 를 걷어 냈는지 확인한다.
- 소수점 `translateZ` 는 래스터화를 어긋나게 한다. 정수로 맞춘다.
- 기울인 상태에서 흐린 것은 정상이다. **기울이지 않은 상태에서 흐린 것이 결함이다.**

## M2 · 적중 영역과 초점이 따라오는가

- 기울인 카드의 버튼을 실제로 누른다. 보이는 자리와 눌리는 자리가 같은가.
- 뒤집힌 면의 포커스 가능한 요소에 탭이 들어가지 않는가(`inert` 또는 `visibility`).
- 시각적으로 재배치한 순서와 DOM 순서가 어긋나지 않는가. 초점은 변환을 따르지 않는다.
- 숨긴 뒷면이 클릭을 가로채지 않는가.

## M3 · 조상이 3D 를 납작하게 만들지 않는가

게이트 D2 는 **같은 규칙 안**의 충돌만 잡는다. 원근 뿌리부터 3D 자식까지의 모든 조상을 개발자 도구에서 훑어, 계산된 `transform-style` 이 실제로 `preserve-3d` 인지 본다. `flat` 으로 계산돼 있으면 그 요소에 걸린 `overflow`·`filter`·`opacity`·`clip-path`·`contain` 중 하나가 범인이다(`css-3d.md` 의 표).

3D 가 "왜인지 안 도는" 경우의 대부분이 여기다.

## M4 · 대상 기기에서 프레임이 나오는가

- 저사양 조건(CPU 4배 스로틀, 모바일 뷰포트)에서 본다. 작성한 기계의 프레임은 증거가 아니다.
- 합성 레이어 수를 본다. 층마다 레이어를 만들면 메모리가 먼저 무너진다.
- 뷰포트 밖에서 멈추는가. 문서가 숨겨졌을 때 멈추는가.

## M5 · 그 깊이가 값을 하는가

이 판정은 배달 엔진이 소유한다 — 엔진 1 의 절제 게이트, 엔진 2 의 크래프트 바닥과 `/freyja2 polish`, 엔진 4 의 슬롭 테스트(`compose.md`). 이 스킬은 기법이 살아 있는지만 판정하고, 그 기법이 있어야 하는지는 판정하지 않는다.

자기 산출물에 스스로 매긴 점수는 리뷰가 아니다. 리뷰라고 부르지 말고 자기 보고라고 적는다.

## 저감 모션은 따로 본다

`prefers-reduced-motion: reduce` 를 켜고 화면을 **다시 연다**. 게이트 D3 는 경로가 존재하는지만 보고, 그 경로가 옳은지는 보지 않는다.

- 최종 상태가 보이는가. 깊이만 꺼졌고 정보는 남았는가.
- 뒤집기 카드의 **뒷면 내용에 도달할 수 있는가.** 회전이 유일한 경로였다면 저감 경로에서 그 정보는 사라진 것이다.
- 스크롤 구동 연출이 최종 상태로 즉시 전환되는가. 스크롤해야만 나타나는 콘텐츠가 남아 있지 않은가.

## 보고 형식

```
깊이 확인
  게이트 · depth_gate 10항 중 판정 n, 통과 n, 경고 n   (JSON 첨부 또는 요약)
  M1 글자 선명도 · 확인함 / 미확인
  M2 적중·초점    · 확인함 / 미확인
  M3 조상 평면화  · 확인함 / 미확인
  M4 프레임 예산  · 확인함(조건 명시) / 미확인
  M5 값어치       · <배달 엔진>의 게이트 판정으로 대체
  저감 모션       · 확인함(무엇이 남고 무엇이 꺼졌는지) / 미확인
```

미확인을 미확인이라고 적는다. 확인하지 않은 항목을 목록에서 빼는 것은 통과로 읽힌다.
