# 조합 — 엔진의 독립을 깨지 않고 얹는 법

이 스킬은 **기법 계층**이다. 엔진이 아니다. 화면을 소유한 엔진이 배달을 소유하고, 여기서 고른 기법은 그 엔진의 게이트를 통과해야 한다.

## 독립 불변 네 조항

1. **파일 불가침.** 이 스킬은 다른 엔진의 플러그인 디렉터리를 읽지도, 실행하지도, 고치지도 않는다. 엔진 쪽에도 이 스킬을 가리키는 배선이 없다.
2. **런타임 불가침.** `depth_gate.mjs` 는 node 내장 모듈만 쓴다. 다른 엔진의 스크립트를 부르지 않고, 다른 엔진의 금고에 쓰지 않는다.
3. **게이트 우선순위.** 사용자의 명시 요청 → 접근성 바닥 → **배달 엔진의 게이트** → 이 스킬의 레시피. 충돌하면 이 스킬이 진다. 예외는 없다.
4. **양방향 제거 가능성.** 이 스킬을 지워도 네 엔진은 그대로 돈다. 어느 엔진을 지워도 이 스킬은 그대로 돈다. 이 조항이 깨지면 기법 계층이 아니라 결합이다.

## 조합표

| 배달 엔진 | 이 스킬이 소유 | 엔진이 소유 | 반드시 도는 게이트 | 꺼지는 칸 |
|---|---|---|---|---|
| **엔진 1** `asgard-freyja-design` | 공간 구성, 변환 값, 저감 경로 | 절제 게이트, `vanadis-final-qa`, 다섯 상태, 금고 `engine1/` | `depth_gate` + final-QA 루브릭 | 절제 게이트가 빼라면 뺀다 |
| **엔진 2** `asgard-freyja2` | 같음 | 모션 논지(`/freyja2 animate`), 크래프트 바닥, 검출기, 금고 `engine2/` | `depth_gate` + `node engine/scripts/detect.mjs` | 첫 페인트를 막는 진입 연출 |
| **엔진 3** `asgard-freyja-3d` | 트윈 계층뿐 | 씬·예산·자산·카메라·룩 바닥, `detect3d`, `scene_audit` | 엔진 3 의 배달 게이트 전체 | L0~L4 는 엔진 3 이 필요 없다 |
| **엔진 4** `asgard-freyja4` | 같음 | 거시구조, 테마, 58항 슬롭 테스트 | `depth_gate` + `node engine/scripts/slop_gate.mjs` | **L2 시차 전면 금지**, 무한 루프, 튕김 |

## 엔진 1 — 절제가 마지막에 온다

`vanadis-feel` 을 먼저 적재하고 절제 게이트를 마지막에 적용하는 순서는 그대로다. 깊이는 그 순서 안의 재료 선택 하나일 뿐이다.

**충돌 하나를 미리 안다.** 엔진 1 의 모션 계약은 "초점과 깊이"의 재료로 **경계 지어진 blur·filter·backdrop** 을 제시한다. 그런데 `filter` 와 `backdrop-filter` 는 3D 문맥을 평면으로 되돌린다(`css-3d.md`). **같은 요소에 둘을 함께 걸 수 없다.** 흐림으로 깊이를 말할지(L1), 투영으로 말할지(L3) 하나를 고르고, 둘 다 필요하면 흐리는 요소와 3D 문맥을 유지하는 요소를 **다른 요소로 나눈다**. 게이트 D2 가 같은 규칙에서의 충돌만 잡으므로, 나눌 때 조상 체인은 사람이 확인한다(미판정 M3).

절제 게이트가 깊이를 빼라고 하면 뺀다. 이 스킬은 "뺄 수 없는 이유"를 제공하지 않는다.

## 엔진 2 — 논지가 먼저, 재료가 나중

1. `/freyja2 animate` 로 모션 논지를 세운다(초점 순간·연속성·피드백·예산). 논지 없이 기법부터 고르지 않는다.
2. 논지가 깊이를 부르면 이 스킬에서 칸과 레시피를 고른다.
3. UI 파일을 고친 뒤와 끝내기 전에 `node engine/scripts/hook.mjs` 를 돌린다. 검출 결과는 요약하지 않고 처리한다.
4. `/freyja2 polish` 로 닫는다.

엔진 2 의 **모션 아키텍처 불변조항**이 이 스킬보다 위에 있다: 콘텐츠가 먼저 칠해지고 연출은 그 위에 더해진다. 깊이 진입 시퀀스 뒤에 첫 페인트를 두지 않는다. 기본 상태는 JS 없이도 보여야 하므로, `perspective` 와 `preserve-3d` 는 CSS 에 두고 anime.js 에는 값만 맡긴다.

## 엔진 3 — 경계선

**L5 로 올라가는 순간 소유권이 넘어간다.** 판단 기준은 `depth-ladder.md` 의 네 가지(가려짐·빛·곡면·카메라)다.

- 이 스킬은 **캔버스를 열지 않는다.** WebGL/WebGPU 컨텍스트를 여는 결정은 엔진 3 의 realtime 레인이 한다.
- anime.js v4 의 three.js 어댑터로 씬 객체를 트윈하는 경우, **트윈 계층만** 이 스킬이 소유한다. 씬 구성·예산·자산·카메라 연출·`detect3d`·`scene_audit` 는 전부 엔진 3 이다.
- 반대 방향도 지킨다. 카드 하나 기울이는 일에 엔진 3 을 부르지 않는다. L0~L4 는 DOM 과 CSS 로 끝난다.
- 두 스킬의 저감 모션 규약은 같다: 저감은 삭제가 아니라 대체.

## 엔진 4 — 금지가 이긴다

마르될의 모션 계약은 이 스킬의 레시피 일부와 **정면으로 충돌하며, 충돌 시 마르될이 이긴다.**

| 마르될의 금지 | 이 스킬에서의 결과 |
|---|---|
| 시차(parallax) 금지 | **R1 을 쓰지 않는다.** 층위가 필요하면 L1(겹침)으로 내려간다 |
| 스크롤 스크럽은 이유가 있을 때만 | R8 은 브리프에 근거를 적고 쓴다. 근거가 없으면 쓰지 않는다 |
| 무한 루프 금지 | R4·R5 의 자동 회전을 걸지 않는다. 게이트 D9 와 같은 방향이다 |
| 튕김·탄성 금지 | `createSpring` 을 UI 요소에 쓰지 않는다. `ease: "out(3)"` 계열로 간다 |
| `transform` 과 `opacity` 만 애니메이션 | R8 의 「빛」을 `box-shadow` 트윈으로 만들지 않는다 — 그림자 층을 따로 두고 그 층의 `opacity` 를 움직인다 |
| 어두운 배경에서 `box-shadow` 발광 금지 | 광택 세기를 테마 규약에 맞춘다 |
| 지속 시간 세 구간(120·220·420ms) | 틸트는 미시 상호작용이다. 240ms 를 넘기지 않는다 |
| `will-change` 광역 선언 금지 | 게이트 D8 과 같은 방향이다 |

마르될 아래에서 실질적으로 열려 있는 칸은 **L1 과 L3(절제된 형태)** 이고, L4 는 브리프가 명시적으로 요구할 때만이다. 두 게이트를 모두 돌린다 — `depth_gate` 는 깊이가 죽지 않았는지, `slop_gate` 는 그 깊이가 슬롭인지 본다. 둘은 서로를 대신하지 않는다.

## 두 엔진을 동시에 쓰는 경우

3D 를 품은 웹 화면에서 엔진 3 이 형상·성능·모션을 맡고 엔진 1 또는 2 가 레이아웃·타이포·카피를 맡는 구성은 정상이다. 이때 이 스킬은 **DOM 쪽 깊이**(오버레이 카드, HUD, 전환)를 맡고 캔버스 안쪽은 건드리지 않는다. 게이트도 각자 돈다: 소스 트리에 `depth_gate` 와 `detect3d` 를 함께 돌리고, 둘의 판정을 합치지 않고 따로 보고한다.
