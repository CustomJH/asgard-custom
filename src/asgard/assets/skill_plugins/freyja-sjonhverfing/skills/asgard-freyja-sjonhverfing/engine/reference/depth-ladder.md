# 깊이 사다리 — 몇 칸까지 올라갈 것인가

깊이는 켜고 끄는 스위치가 아니라 사다리다. 위로 올라갈수록 전달력이 늘지만 비용·결함·접근성 부채가 함께 는다. **뜻을 전달하는 가장 낮은 칸을 고른다.** 한 칸 위가 필요하다는 근거를 말할 수 없으면 그 칸은 장식이다.

| 칸 | 이름 | 재료 | 비용 | 언제 |
|---|---|---|---|---|
| **L0** | 평면 | 없음 | 0 | 깊이가 전달할 것이 없다. 대부분의 화면이 여기다 |
| **L1** | 겹침 | 그림자·겹치기·크기 대비·흐림 | 페인트만 | 층위(무엇이 위에 있는가)만 말하면 될 때 |
| **L2** | 층 시차 | 서로 다른 속도의 `translate` | 합성만 | 무대의 앞뒤 관계를 말할 때. 원근 불필요 |
| **L3** | 투영된 면 | `perspective` + `rotateX/Y` + `translateZ` | 합성 + 3D 문맥 | 면이 공간 안에서 기울어야 뜻이 생길 때(기울기 카드, 뒤집기, 달리) |
| **L4** | 조립된 부피 | 여러 면을 `preserve-3d` 로 묶어 상자·고리·두께 | 3D 문맥 + 정렬 부채 | 물건이 부피를 가진 것처럼 굴어야 할 때(고리 캐러셀, 상자, 두께 글자) |
| **L5** | 진짜 3D | WebGL/WebGPU, 실제 지오메트리·조명·재질 | 런타임 + 예산 + 자산 | 여기서부터는 이 스킬이 아니다 → 엔진 3 |

## 칸을 정하는 세 질문

1. **깊이가 없으면 무엇을 잃는가.** 답이 "덜 예쁘다"뿐이면 L0 또는 L1 이다. 답이 "무엇이 무엇의 뒤에 있는지 모른다"면 L2 다. 답이 "면의 방향을 모른다"면 L3 이다.
2. **사용자가 각도를 바꿀 수 있어야 하는가.** 아니면 L3 위로 갈 이유가 대개 없다. 볼 수 있는 각도가 하나뿐인 부피는 그림이다 — 그림이면 L1 으로 충분하다.
3. **빛과 재질이 뜻의 일부인가.** 금속인지 천인지가 정보라면 L5 다. DOM 으로 흉내 낸 재질은 가까이서 보면 전부 무너진다.

## L4 와 L5 의 경계

DOM 으로 만든 부피는 다음 넷을 못 한다. 하나라도 필요하면 L5 이고, 엔진 3(`asgard-freyja-3d`)이 소유한다.

- **가려짐(occlusion)** — 면끼리 서로를 정확히 가리지 못한다. 브라우저는 요소를 폴리곤이 아니라 평면으로 정렬한다. 교차하는 두 면은 정렬 순서가 튄다.
- **빛** — 그림자·반사·굴절이 없다. 있는 것은 우리가 손으로 칠한 그라디언트뿐이고, 각도가 바뀌면 거짓말이 드러난다.
- **곡면** — 면을 아무리 잘게 쪼개도 곡면이 되지 않는다. 20개를 넘어가면 부피가 아니라 레이아웃 부채다.
- **카메라** — 원근 뿌리는 하나뿐이고 요소가 아니라 무대에 붙어 있다. 카메라가 씬 안을 움직여야 하면 씬이 필요하다.

역방향도 같다. **엔진 3 이 필요하다는 신호가 없는데 캔버스를 여는 것은 과잉이다.** 카드 하나 기울이자고 WebGL 런타임과 자산 예산을 들이지 않는다.

## 칸마다 딸려 오는 의무

| 칸 | 반드시 함께 오는 것 |
|---|---|
| L2 | 저감 모션 경로. 시차는 전정기관 유발 요인이다 |
| L3 | 원근 뿌리 1개, 저감 모션 경로, 회전 후에도 유지되는 적중 영역·초점 |
| L4 | L3 의 전부 + 뒷면 처리, 면 정렬(z-fighting) 확인, 정지 수단 |
| L5 | 엔진 3 의 배달 게이트 전체(형상·예산·`detect3d`·룩 바닥) |

## 흔한 오등급

- **시차를 L3 으로 지은 경우.** 앞뒤 관계만 말하면 되는데 원근과 3D 문맥을 세우면 조상 평면화·적중 영역·글자 선명도 부채를 전부 떠안는다. L2 는 `translate` 하나로 끝난다.
- **뒤집기를 L4 로 지은 경우.** 카드 뒤집기는 면 두 장이다. 상자를 만들 이유가 없다.
- **부피를 L1 으로 흉내 낸 경우.** 그림자 여덟 겹으로 만든 가짜 두께는 각도가 하나로 고정될 때만 산다. 사용자가 기울일 수 있으면 L4 로 올리거나, 기울이기를 뺀다.
