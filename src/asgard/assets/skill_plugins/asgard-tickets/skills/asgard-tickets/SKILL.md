# 일감을 적으면서 일한다

보드는 소원 목록이 아니라 **무슨 일이 실제로 있었는지의 기록**이다. 그러려면 티켓이 일이
끝난 뒤가 아니라 **일하는 동안** 움직여야 한다.

정본은 `ticket` 툴 하나다. 파일을 직접 만들지 않는다 — 사람이 창에서 보는 그 보드와 같은
저장소여야 대화가 이어진다.

## 형상 (Linear 와 같은 어휘)

```
워크스페이스 ── 팀 ── 티켓            팀이 번호의 주인이다 (NOR-12)
      │          └─ 워크플로 상태 · 사이클 · 트리아지
      ├─ 프로젝트 ── 마일스톤          끝이 있는 일. 팀을 가로지른다
      └─ 이니셔티브 ── 프로젝트 묶음
```

- **보드는 폴더에 안 매인다.** 읽기는 늘 워크스페이스 전체다 — 어느 저장소에서 부르든 같은
  목록이 온다. 좁히려면 `team="<키>"`, 이 폴더에 결속된 팀만 보려면 `team="."`.
- **팀**은 사람이 짓는다. 결속해 둔 폴더에서 적으면 그 팀에, 아니면 워크스페이스 기본 팀에
  적힌다 — 폴더가 스스로 팀이 되지는 않는다.
- **티켓은 팀 하나에만** 속한다(번호의 주인). **프로젝트 하나에만** 속한다(진척의 단위).
- 상태 이름은 팀이 짓는다. `in_progress` 가 없는 팀도 있다 — 외우지 말고 `list`/`get` 이
  돌려주는 이름을 쓴다.

## 언제 티켓을 여는가

**시키신 일이 한 줄로 안 끝나면 먼저 연다.** 파일 두 개 이상을 건드리거나, 단계가 셋 이상
이거나, 되돌리기가 필요한 일이 그렇다.

```
ticket(action="list", open_only=true, query="<핵심어>")   ← 이미 있는지부터
ticket(action="create", title="<결과로 적은 제목>", body="<맥락·수용 기준>")
ticket(action="start", ref="NOR-12")                      ← 손대기 시작할 때
… 실제 작업 …
ticket(action="finish", ref="NOR-12", text="<무엇을 바꿨는지 한 줄>")
```

`finish` 는 **완료가 아니라 검토 중**으로 옮긴다. 프로세스가 0으로 끝난 것과 사람이
받아들인 것은 다른 일이라, 완료는 사람이 누른다.

**한 줄로 끝나는 일에는 열지 않는다.** 오타 하나, 질문 하나, 파일 하나 읽기 — 그런 것까지
번호를 받으면 보드가 잡음이 되고, 잡음이 된 보드는 아무도 안 본다.

## 지나가다 본 것도 적는다

지금 하지 **않는** 일을 발견했을 때가 티켓의 본래 자리다.

- 다른 것을 고치다 본 결함
- 사용자가 미룬 것("나중에", "이번엔 말고")
- 건너뛴 단계, 우회한 한계
- 큰 요청에서 떼어 낸 조각

이때는 `create` 만 하고 `start` 하지 않는다. 그리고 **보고문에 번호를 적는다** — 번호가
없으면 사용자는 그것을 찾을 방법이 없다.

## 제목은 결과로

| 안 됨 | 됨 |
|---|---|
| 결제 재시도 | 결제 재시도에 지수 백오프 적용 |
| 로그인 개선 | 로그인 실패 시 남은 시도 횟수 표시 |
| 리팩터링 | 주문 조회를 단일 쿼리로 합쳐 N+1 제거 |

주제는 끝낼 수 없고 결과는 끝낼 수 있다. 본문에는 **재현·제약·수용 기준**을 적는다.

## 프로젝트에 붙일 때

여러 팀에 걸치거나 목표일이 있는 일이면 프로젝트에 붙인다.

```
ticket(action="projects")                                  ← 있는 것만 쓴다
ticket(action="create", title="…", project="결제 개편", milestone="베타")
```

**프로젝트 이름을 지어내지 않는다.** 없으면 사람에게 만들지 물어본다 —
`asgard ticket project --new "이름"` 이 그 손이다.

## 트리아지가 켜진 팀

에이전트가 끊은 티켓이 사람의 백로그에 곧장 섞이면 백로그는 곧 아무도 안 보는 목록이 된다.
그래서 팀이 트리아지를 켜 두면 새 티켓은 **인박스**에 선다. 툴이 그렇게 말해 주면
(`팀 인박스(트리아지)에 세웠습니다`) 보고문에 그대로 옮긴다 — 사람이 받아야 보드로 간다.

## 무엇을 할지 물으면

```
ticket(action="list", open_only=true)   ← 기본이 워크스페이스 전체다
```

우선순위 순으로 온다(긴급이 먼저, '없음'이 맨 뒤). 막힌 것(`막힘 ←`)은 지금 할 수 없는
것이니 권하지 않는다.

## 사용자에게 안내할 것

티켓을 처음 만든 자리에서는 **무엇이 왜 생겼는지** 한 줄로 말한다. 모르는 사이에 번호가
생기면 사용자는 그것을 자기 것으로 안 읽는다.

> `NOR-12` 로 적어 두고 진행합니다. 창에서는 `asgard open studio` 의 업무 화면, 터미널에서는
> `asgard ticket board` 로 같은 보드를 봅니다.

## 하지 않는 것

- 방금 끝낸 일을 티켓으로 만들지 않는다 — 그건 보고문이다(진행 중이던 티켓을 `finish` 로
  옮기는 것은 다르다).
- 열려 있는 티켓이 이미 덮는 일을 두 번 열지 않는다.
- 사람의 티켓 상태를 묻지 않고 `done` 으로 옮기지 않는다.
- 번호를 지어내지 않는다. `NOR-12` 를 말하려면 그 번호가 툴에서 나온 것이어야 한다.
