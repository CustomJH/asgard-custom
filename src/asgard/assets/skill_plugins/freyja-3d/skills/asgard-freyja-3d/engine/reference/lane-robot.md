# robot 레인 — 로봇 기술 파일

URDF·SRDF·SDF. **XML 을 쓰는 일이 아니라 구속된 운동학을 모델링하는 일이다.** 오류가 나는 자리는 문법이 아니라 좌표계 배치, 조인트 축 의미, 단위 일관성, 메시 스케일, 관성값이다.

이 레인은 LLM 이 구조적으로 약한 영역이다 — 공간·운동학 추론. 그래서 규율 하나가 다른 모든 것보다 앞선다: **말이나 그림에서 변환을 추론하지 않는다.** CAD 변환값, 치수가 적힌 도면, 실측값, 기존 소스 데이터, 아니면 **명시적으로 적은 가정**에서만 가져온다.

## 셋의 경계

| 형식 | 소유하는 것 | 넣지 말아야 할 것 |
|---|---|---|
| **URDF** | 물리 구조 — 링크, 조인트, 형상, 관성, 한계, mimic, 트랜스미션 | 계획 의미론, 시뮬레이터 물리 |
| **SRDF** | MoveIt 의미론 — 가상/수동 조인트, 계획 그룹, 그룹 상태, 엔드이펙터, 비활성 충돌쌍 | 형상·관성·조인트 원점·링크 포즈·메시 참조·물리 한계·`ros2_control` |
| **SDF** | 시뮬레이터·월드 — 물리, 센서, 조명, 플러그인, 월드, 메타데이터 | 계획 의미론 |

**SDF 는 SDFormat 이지 signed-distance-field 가 아니다.** SDF 조형은 `lane-implicit.md`. 이름이 같아서 생기는 사고를 여기서 끊는다.

## 공통 규약

1. **`gen_urdf()`/`gen_srdf()`/`gen_sdf()` 를 정의한 파이썬이 정본**이고, `.urdf`/`.srdf`/`.sdf` 는 생성물이다. 생성된 XML 을 직접 고치지 않는다.
2. **명시한 대상만 생성한다.** 디렉터리 전체 재생성을 하지 않는다.
3. **쓰기 전에 설계 원장(design ledger)을 만든다** — 좌표계, 조인트, 형상, 단위, 가정. 각 스킬의 `references/design-ledger.md`(SRDF 는 `planning-ledger.md`).
4. 생성 시점 검증이 기본으로 돈다. **별도 `validate` 명령을 쓰거나 문서화하지 않는다.**
5. 단위는 SI — 미터·킬로그램·초·라디안. **SRDF 그룹 상태에 도(degree)를 넣지 않는다.**
6. 숫자를 XML 문자열 리터럴에 묻지 않는다. 물리적 의미로 이름 붙인 상수를 쓴다.

```bash
CAD=engine/scripts/cad.py
python $CAD urdf robot.py
python $CAD srdf robot_semantics.py
python $CAD sdf  world.py
```

## URDF

- 대상 소비자를 먼저 정한다: RViz, robot_state_publisher, Gazebo/Ignition, MoveIt, 실제 로봇 드라이버.
- **URDF 좌표계 의미를 정확히 쓴다.** 조인트 원점, 링크 좌표계, 조인트 축, visual/collision/inertial 원점은 **서로 다른 기준계**를 쓴다. `references/frame-semantics.md` 를 적재한다. 이것이 이 레인 오류의 1번 원인이다.
- 물리 링크는 `inertial`·`visual`·`collision` 을 소비자가 필요로 하는 만큼 따로 모델링한다. 좌표계 전용 링크는 질량·형상을 의도적으로 생략할 수 있다.
- 형상·메시 참조가 CAD 산출물에 의존하면, **CAD 를 먼저 재생성하고** URDF 를 다시 낸다. 순서를 뒤집으면 메시가 옛것을 가리킨다.

## SRDF

**유효한 URDF 에서 시작한다.** SRDF 는 그 위의 계획 의미론이고, 없는 구조를 만들지 못한다.

실패는 대개 "무효한 XML"이 아니라 **그럴듯한데 틀린 SRDF** 다 — 잘못된 계획 그룹, 잘못된 툴 링크, 잘못된 기본 자세, 위험한 비활성 충돌 행렬.

- 계획 그룹은 **URDF 위상에서** 유도한다. 직렬 매니퓰레이터는 base/tip 이 실제 경로를 이루면 체인 그룹.
- 엔드이펙터는 그룹 멤버십이 정해진 **다음에** 정의한다. 부모 그룹과 겹치지 않게 한다.
- **비활성 충돌쌍은 증거에서 나온다** — 인접성, MoveIt Setup Assistant 샘플링, 사용자가 준 행렬. 넓은 비활성 목록을 지어내지 않는다. 이것은 안전 문제다.
- 그룹 상태는 URDF 네이티브 단위로: revolute·continuous 는 라디안, prismatic 은 미터.

## SDF

- 문서 종류를 먼저 정한다: 모델 수준 / 월드 수준 / 월드 안의 모델. 재사용 가능한 로봇·물체 내보내기는 모델 수준을 택한다.
- 새 출력은 `version="1.12"` 를 기본으로 하되 소비자가 제약하면 따른다.
- 생성 후 가능한 검사를 돌린다: 번들 검증, `gz sdf --check`, 시뮬레이터 로드, 조인트 구동, 플러그인·센서 기동.

## 리뷰

`.urdf`·`.srdf`·`.sdf` 는 `lane-viewer.md` 의 로컬 뷰어에서 원문으로 연다.

**SRDF 는 URDF 와 같이 검증한다** — `python $CAD srdf check robot.srdf --urdf robot.urdf`. 이때만 존재하지 않는 링크를 가리키는 계획 그룹, URDF 한계를 벗어난 그룹 상태, 라디안 자리에 들어온 도(degree), 근거 없이 넓은 비활성 충돌 행렬이 잡힌다. URDF 없이 돌린 SRDF 검증은 문법 검사에 지나지 않고, 도구가 그 사실을 미확인으로 적는다.

IK·경로 계획을 대화적으로 보려면 MoveIt2 환경이 따로 필요하다(conda·ROS). 이 엔진의 범위 밖이므로 사용자가 그 상호작용을 실제로 필요로 할 때만, 설치 비용을 먼저 말하고 켠다.

## 보고

**확인하지 않은 공간 데이터를 확인한 것처럼 적지 않는다.** 이 레인의 보고에는 항상 셋이 들어간다:

```text
- 가정: 메시 단위 mm 로 가정(소스에 선언 없음), 베이스 좌표계 원점을 바닥 중심으로 둠
- 확인하지 않은 것: 관성 텐서는 균일 밀도 근사 — 실측 아님
- 검사 공백: MoveIt 환경이 없어 스모크 테스트 미실행
```

로봇 기술 파일은 실물 장비를 움직이는 데 쓰인다. 미확인을 침묵으로 두지 않는다.
