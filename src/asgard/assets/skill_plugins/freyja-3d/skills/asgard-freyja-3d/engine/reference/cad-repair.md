# 수리 루프

생성·내보내기·조사·배치·스냅샷·뷰어가 실패했을 때.

## 루프

1. 실패한 명령의 출력을 **읽는다.** 트레이스백이 곧 수리 단서다.
2. 실패를 분류한다(아래).
3. **책임 있는 가장 작은 자리**를 고친다. 주변을 같이 손대면 무엇이 고쳤는지 모른다.
4. 실패했던 명령을 다시 돌린다.
5. 그것에 의존하는 검사도 다시 돌린다.
6. 남은 위험이나 의도적 편차를 보고한다.

## 분류

### 소스 임포트·문법 실패
문법 오류, 임포트 누락, 잘못된 build123d 심볼, 함수 이름이 `gen_step()` 이 아님, 함수 밖 실행 코드의 부작용.
→ `gen_step()` 이 STEP 준비된 형상이나 Compound 를 반환하게 한다. 출력 경로는 CLI 가 갖는다, 반환값에 넣지 않는다.

### 형상이 없거나 무효
열린 스케치, 대상 밖의 절삭 프로파일, 0 두께, 실패한 불리언, 내보내기용으로 쓴 구성 형상.
→ 면이 될 프로파일을 닫는다. 치수가 양수인지 본다. 관통 컷은 도구를 양쪽으로 넘긴다. 실패한 피처를 단순화해 점진적으로 다시 쌓는다.

### 필렛·챔퍼 실패
반경이 지역 형상보다 크다, 선택 에지에 의도치 않은 미세 에지가 섞였다, 불리언이 만든 복잡한 에지 위상.
→ 반경을 줄인다. 에지 선택을 좁힌다. 필렛을 더 뒤로 민다. 피처 의도별로 에지 그룹을 나눈다.

### 스케일·바운딩 박스가 틀림
단위 불일치, 지름/반지름 혼동, 압출 방향·양, 가정과 다른 중심, 수입 STEP 의 예상 밖 단위.
→ 파라미터 값을 확인하고 `refs --facts` 로 실측을 읽는다.

### 피처가 없다
`Mode.ADD`/`Mode.SUBTRACT` 반대, 프로파일이 대상 안에 없다, 막힌 컷이 얕다, 앞선 연산 후 셀렉터가 바뀌었다.
→ 모드를 확인하고, 관통 컷 길이를 늘리고, 위상·평면을 다시 조사한다.

### 셀렉터 취약성
임의 인덱스 선택, 필렛·불리언 후 위상 변화, 구분 안 되는 비슷한 면들.
→ 축·평면·위치·법선으로 고른다. `refs --facts --planes --positioning` 으로 안정적인 참조를 다시 발굴한다. **셀렉터는 쓰기 직전에 다시 딴다.**

### 배치·조인트 불일치
부품 지역 원점·데이텀이 틀림, `AssemblyHelper` 고정/이동 순서가 뒤집힘, `connect_to()` 가 반대쪽을 옮김, 조인트 축 반전, 대칭 배치 부호 오류, 파라미터 변경 후 재계산되지 않은 명시 `Location`, 지역 데이텀을 의도했는데 월드 좌표로 정의된 조인트.
→ `refs --positioning` → `frame` → `align` 순으로 좁힌다. `cad-assembly.md` 의 "어긋났을 때 고칠 자리" 목록에서 가장 작은 것을 고른다. **STEP 을 직접 패치하지 않는다.**

### 스냅샷 실패
입력 경로가 STEP/STP 도 동일 스템 생성기도 아니다, 위상 산출물이 없다, 렌더 플래그가 잘못됐다.
→ STEP 을 먼저 생성한 다음 그 `.step` 을 대상으로 찍는다. 단순한 `view` 한 장부터 다시 시도하고 거기서 늘린다.

### 뷰어 실패
node 없음, 포트 충돌, `?dir=` 가 절대경로가 아니다, `file=` 이 `dir` 밖을 가리킨다.
→ `lane-viewer.md` 의 실측된 기동 절차를 따른다. 그래도 안 되면 **뷰어 없이 진행한다** — CLI 사실·측정·스냅샷이 검증의 본체이고 뷰어는 편의다.

## 고친 뒤

무관한 형상이 변했을 수 있으면 확인한다:

```bash
python engine/scripts/cad.py inspect diff before.step after.step --planes
```

## 못 고쳤을 때 보고

```text
- 무엇이 실패했는가
- 무엇을 시도했는가
- 어떤 산출물이 아직 쓸 만한가
- 어떤 검증 주장을 할 수 없는가
- 다음에 고칠 소스 자리는 어디인가
```

못 고친 것을 안 고친 척하지 않는다. 마지막 두 줄이 이 문서에서 가장 중요하다.
