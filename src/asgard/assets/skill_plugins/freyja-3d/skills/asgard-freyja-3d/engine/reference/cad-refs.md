# 셀렉터 참조와 검증 동사

STEP 을 만든 다음 "맞는지" 확인하는 층. 이 문서가 없으면 검증은 "코드를 다시 읽어봤다"로 퇴화한다.

## 왜 참조가 필요한가

형상의 특정 면·에지·부품을 **이름으로 부를 수 있어야** 치수를 잴 수 있다. `#o1.2.f1` 같은 토큰이 그 이름이다. 이름이 없으면 "윗면이 6mm 위에 있다"는 말은 검증이 아니라 주장이다.

## 문법

셀렉터는 대상 STEP 파일 **안에서만** 유효한 지역 토큰이다. 파일 경로는 따로 인자로 넘긴다.

```text
#o1          — 어커런스(조립 트리의 배치된 노드)
#o1.2        — 중첩 어커런스
#o1.2.f1     — 그 어커런스의 1번 면
#f1          — 면 (어커런스가 하나면 생략 가능)
#e7          — 에지
#s1          — 셰이프(어커런스 안의 몸통)
#v3          — 버텍스
```

위상은 `어커런스 → 셰이프 → 면 → 에지` 순으로 내려간다. 면과 에지는 셰이프에 속하고, 셰이프는 어커런스에 속한다.

**서수는 안정적이지 않다.** `#f7` 은 파라미터를 바꾸면 다른 면이 된다. 그래서 규칙 하나: **셀렉터는 쓰기 직전에 `refs` 로 다시 딴다.** 대화 앞에서 본 번호를 기억해서 재사용하지 않는다.

## 동사

```bash
CAD=engine/scripts/cad.py

python $CAD inspect refs    <target> [selectors...] [--facts --planes --positioning --detail --topology]
python $CAD inspect measure <target> --from '#a' --to '#b' --axis z
python $CAD inspect align   <target> --moving '#a' --target '#b' --mode flush|center --axis z
python $CAD inspect frame   <target> '#selector'
python $CAD inspect diff    <before> <after> [--planes]
```

| 동사 | 무엇을 답하는가 |
|---|---|
| `refs` | 이 형상에 무엇이 있는가 — 크기, 솔리드 수, 라벨, 주요 평면, 배치 가능한 참조 |
| `measure` | 두 참조 사이 거리 — 살두께, 간극, 오프셋, 구멍-면 거리 |
| `align` | 두 참조가 맞닿아야 하는데 얼마나 어긋났는가 (읽기 전용 델타) |
| `frame` | 이 참조의 월드 좌표계 — 방향이 맞는가, 축이 X/Y/Z 와 정렬됐는가 |
| `diff` | 고치기 전후로 **의도하지 않은 곳**이 변했는가 |

`align` 은 **판정 도구지 편집 도구가 아니다.** 델타를 돌려줄 뿐 STEP 을 고치지 않는다. 어긋났으면 소스에서 고치고 다시 생성한다.

## 검증 순서

1. STEP 이 생겼고 비어 있지 않다.
2. `refs --facts --planes --positioning` — **모든 생성물에 예외 없이.** 여기서 크기·라벨·평면 기준이 나온다.
3. 명세 기반 검사 — 사용자가 말한 치수마다 `measure`, 맞닿아야 하는 면마다 `align`, 방향이 걸린 곳마다 `frame`.
4. 수정 과업이면 `diff` 로 무관한 형상이 안 변했는지 본다.
5. 스냅샷(`cad-snapshot.md`) — 그리고 눈에 걸린 것은 전부 위 동사 중 하나로 되돌려 확인한다.

## 셀렉터를 찾는 법

`refs --planes` 는 평면과 좌표를 주지만 면 서수는 주지 않는다. 특정 면의 번호가 필요하면 상세를 편다:

```bash
python $CAD inspect refs model.step --topology            # 면·에지 서수 목록
python $CAD inspect refs model.step '#f13' '#f14' --detail   # 각 면의 법선·중심·bbox·면적
```

`--detail` 이 주는 `normal` 과 `bbox` 로 "이 서수가 내가 생각한 그 면인지"를 확인한 다음 측정에 쓴다. 확인 없이 서수를 믿는 것이 이 레인에서 가장 흔한 조용한 오답이다.

`--topology` 는 큰 모델에서 비싸다. 평소에는 `--facts --planes` 로 충분하고, 셀렉터 발굴·복잡한 디버깅에만 편다.

## 보고

실제로 돌린 검사만 적는다.

```text
검증:
- STEP 생성: 통과
- 솔리드/조립: 2개 — base, lid
- 바운딩 박스: 120 × 80 × 35 mm
- 명세 치수: 판 두께 6.0mm (#f13→#f14, z) — 요청 6mm 일치
             리드 시트 간극 0.00mm (#o1.1.f3→#o1.2.f1, z) — flush 의도대로
- 미확인: 보스 높이는 재지 않았다
```

주장하지 않는 것: 구조 안전성, 공정 인증, 공차 준수, 기하학적 타당성을 넘는 제조 가능성. 해당 해석을 실제로 돌렸을 때만 말한다.

**침묵은 통과가 아니다.** 재려다 못 잰 것은 "미확인"으로 적는다.
