# 스냅샷 — 형상을 눈으로 대조하는 층

## 규율

**만들거나 눈에 보이게 바꾼 STEP 은 전부 스냅샷을 찍고 실제로 연다.** 결정론 검사가 전부 통과했다는 사실은 건너뛸 이유가 되지 못한다 — 결정론 검사는 자기가 부호화한 것만 잡고, "요청한 물건과 닮았는가"는 부호화되지 않는다.

근거: CADCodeVerify(ICLR 2025)·EvoCAD·3DCodeBench 이 공통으로 보고하는 것 — 렌더를 되먹이는 루프가 있을 때만 형상 오류가 잡힌다.

건너뛰어도 되는 경우는 셋뿐이고, **건너뛴 이유를 적는다**:

- 형상이 눈에 보이게 바뀌지 않은 순수 포맷·내보내기 요청
- 조사 전용 과업(측정 질문 등) — 만들거나 고친 것이 없다
- 파이썬·STEP 생성이 실패해서 판정할 산출물 자체가 없다

스냅샷을 **돌리지 않는다**. 소스를 고쳐 형상이 실제로 변했을 때, 또는 특정 시각적 의심을 확인할 때만 다시 찍는다.

## 두 렌더러의 분업

| 도구 | 무엇을 그리는가 | 무엇에 쓰는가 |
|---|---|---|
| `snapshot` (벤더링, playwright+three.js) | CAD 워크벤치 뷰 — 면 + **에지 라인워크**, 단면, 은선, 와이어프레임, 궤도 GIF | **형상 대조의 정본.** STEP/조립체 리뷰 |
| `shoot.mjs` (무의존, node 내장) | 위치와 면 법선만 | 설치·브라우저가 막힌 환경의 대체, 빠른 형상 확인 |

`shoot.mjs` 는 재질·텍스처·IBL·톤매핑을 그리지 않는다. **룩 판정에 쓰지 않는다.** `snapshot` 도 CAD 워크벤치 뷰이지 뷰티 렌더가 아니다 — 룩이 납품물이면 실제 DCC/엔진/브라우저의 렌더를 따로 열고 `look-floor.md` 로 판정한다.

## 기본 패킷

단순한 부품은 PNG 한 장이면 된다. 아래 조건 중 하나라도 걸리면 4장 패킷을 쓴다:

- 조립체이거나 몸통이 둘 이상
- 여러 면·여러 축에 구멍이 있다
- 셸·내부 공동·보어·통로·개방형 외함처럼 단면이 걸린 형상
- 리브·거싯·보스·스탠드오프·슬롯·패턴 반복
- 형상·불리언·셀렉터·피처 실패를 고친 직후
- "요청한 물건처럼 보이는가"가 과업의 일부인 경우

```json
{
  "input": "models/part.step",
  "mode": "view",
  "outputs": [
    { "path": "shots/iso.png",          "camera": "iso" },
    { "path": "shots/iso_opposite.png", "camera": { "direction": [-1, 1, -0.8] } },
    { "path": "shots/top.png",          "camera": "top" },
    { "path": "shots/front.png",        "camera": "front" }
  ],
  "render": { "viewLabels": true, "padding": 0.12, "sizeProfile": "diagnostic" }
}
```

```bash
python engine/scripts/cad.py snapshot --job shots.json
```

마주 보는 iso 두 장이 핵심이다 — 뒤·좌·아래 면이 **의심해서가 아니라 기본으로** 한 장에는 잡힌다. top 은 패턴·대칭 검사, front 는 실루엣 검사.

파일 이름 뒤에는 공유 UTC 초 타임스탬프가 붙는다(`iso.png` → `iso_20260727T114405Z.png`). 보고에 경로를 적을 때는 실제로 저장된 이름을 적는다.

## 필요할 때만 더하는 것

- **참조 이미지 재현**: 그 이미지의 시점으로 한 장 더 찍어 나란히 놓는다
- `"mode": "section"`: 셸·보어·내부 공동·막힌 구멍·벽 두께 관계
- `display.mode`: `solid`(기본, 에지 있음) · `rendered`(에지 없음) · `transparent`(겹침·간섭 가독성) · `hidden_edges`(가려진 에지까지) · `hidden_lines_removed`(선 위주) · `wireframe`(내부 간섭 의심)
- `--focus '#o1.2'` 로 특정 부품만, `--hide '#o1.2'` 로 특정 부품만 뺀다. **둘을 한 명령에 섞지 않는다.** 어커런스 참조만 받고 면·에지는 못 받는다.
- 복잡한 조립체는 `render.sizeProfile` 을 `assembly`(1800×1200) 또는 `assembly-large`(1920×1440) 로

## 본 것을 판정으로 바꾸는 규칙

**시각 검토는 진단이지 판정이 아니다.** 눈에 걸린 것은 전부 결정론 검사로 되돌려 확인한 뒤에야 검증 주장이 된다.

| 눈에 보인 것 | 되돌릴 검사 |
|---|---|
| 구멍 패턴이 비대칭으로 보인다 | 구멍 중심을 `measure` 로 재고 오프셋 비교 |
| 리드·자식 부품이 어긋나 보인다 | `frame` 으로 어커런스 좌표계, `align` 으로 메이팅 델타 |
| 거싯·보스·리브가 떠 있어 보인다 | 솔리드 수·라벨·접촉 거리 |
| 공동·보어·막힌 구멍이 이상하다 | `section` 으로 다시 보고, 벽 두께·깊이·관통 여부를 `measure` |
| 반복 패턴 간격이 고르지 않다 | 패턴 중심·각도 간격·어커런스 좌표계 |

## 보고

최종 보고에는 저장된 PNG/GIF 경로를 적거나, 건너뛴 이유를 적는다. 시각적으로 발견한 것에는 그것을 뒷받침한 결정론 검사를 같이 적는다.

**렌더를 만들었다는 사실은 본 것이 아니다.** 이미지를 실제로 열지 않고 "확인했다"고 쓰지 않는다. `cad_gate` 의 `snapshot-missing` 은 렌더가 아예 없는 경우만 잡는다 — 만들고 안 본 것은 기계가 잡지 못하고, 그래서 규율로 남는다.
