# critique3d — 3D 산출물 판정 프로토콜

엔진 2 의 critique 를 3D 로 이식했다. 목적은 같다: **자기 산출물에 스스로 매긴 점수를 리뷰라고 부르는 것을 막는다.** 판정은 서로 못 보는 두 평가의 합성으로만 성립하고, 스냅샷으로 남아 다음 실행의 회귀 기준이 된다.

## 불변 조항

- 평가 A(룩 리뷰)와 평가 B(결정론 측정)는 **둘 다 필수**다.
- 서브에이전트/Task 도구가 있으면 A·B 는 **격리된 두 서브에이전트**로 돈다. 인라인 실행은 도구가 없을 때만 허용되는 강등이다.
- 강등했으면 보고 첫 줄에 배너를 단다: `강등: 단일 문맥 (<이유>)`. 조용한 강등은 실패한 판정이다.
- 평가 A 가 끝나기 전에 검출기 출력이 합성 문맥에 들어가면 안 된다. 결정론 출력도 판단을 앵커링한다.
- 형상 시트가 없으면 판정하지 않는다 — `shoot.mjs` 를 먼저 돌려 증거를 만든다. 재질·조명·구도 축을 채점하려면 실제 DCC/엔진/브라우저의 뷰티 렌더도 필요하다. `shoot`만으로 룩을 채점하지 않는다.
- 실행하지 않은 측정을 통과로 적지 않는다(verify.md 보고 규약 그대로).

## 절차

1. **대상 해석** — 산출물 파일(GLB·STL·씬 소스)로 좁힌다. `node engine/scripts/critique_store.mjs slug <대상>` 이 0 이 아니면 저장·추세 없이 판정만 진행한다.
2. **증거 생성** — `shoot.mjs` 4면 이상(front, right, top, iso)으로 형상 시트를 만든다. 룩이 쟁점이면 실제 렌더러의 3/4 뷰티 렌더와 중립 룩뎁 렌더를 추가한다. 실시간 씬은 소스 경로와 런타임 캡처를 함께 확보한다.
3. **평가 A: 룩 리뷰** (서브에이전트) — 형상 시트와 실제 뷰티 렌더를 **실제로 열어 보고** 소스를 읽되, 검출기 출력 없이. look-floor.md 의 검증·거부 목록과 아래 채점표로 축마다 0–4 점. 뷰티 렌더가 없으면 재질·조명·구도 축은 미확인으로 둔다. 강점 2–3, 우선 결함 3–5(각각 P0–P3), 놓친 기회.
4. **평가 B: 결정론 측정** (서브에이전트) — `detect3d --json`(실시간 소스), `scene_audit --json`(GLB), `mesh_audit --json`(제조 대상), 예산은 budgets.md 기준. 숫자와 규칙 이름만 보고한다. 해석하지 않는다.
5. **합성** — 두 보고를 짜서 엮는다(단순 병기 금지): 어디서 일치했고, 검출기가 룩 리뷰가 놓친 것을 잡았고, 어떤 검출이 오탐인지. 첫 줄에 실행 방식을 선언한다: `방식: 이중 에이전트` 또는 강등 배너.

## 채점표 — 8축, 축당 0–4

| 축 | 4 점의 기준 | 해당 없음 조건 |
|---|---|---|
| 실루엣·조형 | 섬네일 크기에서도 무엇인지 읽히고, 비례가 레퍼런스·명세와 일치 | — |
| 재질 | PBR 보정 범위 안, 러프니스에 변주, 마모·그라임이 이야기를 따름 | 미채색 형상 검토 단계 |
| 조명 | 키 방향이 의도된 결정, 환경광 존재, 접지 그림자 | 제조 전용 산출물 |
| 구도·프레젠테이션 | 초점거리·앵글이 용도에 맞게 선택됨, 배경 결정됨, 부유물 없음 | 제조 전용 산출물 |
| 정확성 | 명세의 치수·특징이 렌더·측정에서 하나씩 대조 확인됨 | 명세 없는 탐색 스케치 |
| 기술 위생 | 예산 통과, detect3d FAIL 0, 수밀·간섭 통과 | — |
| 모션 | 선언한 모션이 실제 트리거로 확인됨, 저감 경로 존재 | 정지 렌더 납품 |
| 견고성·접근성 | 로딩·실패 폴백, 컨텍스트 손실 처리, 텍스트 대안 | 정지 렌더 납품 |

- 합계는 **적용된 축 × 4** 를 분모로 적는다(`26/32` 처럼). 해당 없음을 강제로 채점하지 않고, 전체 분모 위에 부분 점수를 적지 않는다.
- 4 는 진짜 뛰어남이다. 실제 산출물 대부분은 60–80% 대에 있다.
- 판정 등급은 백분율로 읽는다: 90%+ 뛰어남 · 70%+ 좋음 · 50%+ 수용 가능 · 30%+ 부족 · 미만 재작업.

## 스냅샷과 추세

보고를 확정하면 저장한다:

```bash
FREYJA3D_CRITIQUE_META='{"target":"<사용자 표현>","total_score":26,"max_score":32,"na_axes":"모션,견고성","p0_count":0,"p1_count":2}' \
  node engine/scripts/critique_store.mjs write <해석된 대상> <본문파일>
node engine/scripts/critique_store.mjs trend <해석된 대상> 5
```

- 본문 임시 파일은 쓰고 나서 지운다.
- 추세 한 줄을 보고 끝에 붙인다: `추세 (최근 5회): 18/32 → 24/32 → 26/32`. 분모가 다르면 각자 분모를 붙여 적고 동일 비교가 아님을 말한다. 첫 실행이면 그렇게 적는다.
- 저장 실패는 판정을 막지 않는다 — 오류를 적고 넘어간다.
- 대상당 최근 5개만 남는다(스크립트가 스스로 자른다).

## 판정 뒤

발견에 근거한 질문 2–3개로 다음 작업의 방향·범위를 좁힌다(일반론 질문 금지). 답을 받으면 우선순위대로 레인·조치에 사상한다: 조형 결함 → cad/art 레인 재작업, 재질·조명·구도 → lookdev.md 적재 후 룩뎁 패스, 기술 위생 → 해당 감사 스크립트의 FAIL 목록, 모션 → lane-motion.md. 수리 뒤 재판정으로 추세를 확인한다.
