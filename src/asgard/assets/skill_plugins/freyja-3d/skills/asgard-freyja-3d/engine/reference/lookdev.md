# 룩뎁 — 조명·카메라·프레젠테이션

치수가 맞는 형상을 프로처럼 **보이게** 만드는 공정이다. 여기의 숫자는 취향이 아니라 현업 표준(출처는 research.md 룩뎁 절)이고, 기계용 정본은 `engine/data/lookdev.json` 과 `engine/data/asset_catalog.json` 이다. 판정 바닥은 look-floor.md 가 쥔다 — 이 문서는 바닥 위에서 방향을 고르는 법이다.

## 조명은 비율이다

- 키:필 비율이 톤을 결정한다: **2:1 상업·친근, 3:1 표준 시작점, 8:1 드라마**. 룩뎁 보정 리그는 3:1–4:1 중립 HDRI 로 고정한다.
- 배치의 관례(Birn): 키는 카메라에서 옆 15–45° · 위 15–45°. 필은 반대편 비대칭, 키의 1/2~1/8. 림은 피사체 뒤 위 — 윤곽선이 또렷해질 때까지.
- 면의 "1, 2, 3 읽기"(KeyShot 관례): **림이 가장 밝고, 키가 다음, 필이 가장 어둡다** — 세 강도가 표면의 세 방향을 구분해 읽게 만든다.
- 부드러움은 광원의 **각크기**다: 면광이 클수록·가까울수록 부드럽다. 제품에 점광 키를 놓은 면도날 그림자는 초보 티다.
- 3점 조명은 공식이 아니다. "모든 장면을 같게 만드는 핑계"가 되는 순간 실패다 — 빛에는 동기가 있어야 한다(어디서 오는 빛인가).

## HDRI 실무 — 회전이 기술이다

- **회전 = 키 리플렉션의 배치다.** 가장 밝은 소스가 3/4 면에 반사될 때까지 돌린다. 무회전 기본 방치는 "설정 안 함"이다.
- 무드 선택은 asset_catalog 의 실명 슬러그에서: studio_neutral(중립 스튜디오) / golden_hour / daylight / overcast / night / indoor_industrial. 색온도 앵커: 골든아워 3000–3500K, 텅스텐 3200K, 주광 5600K, 흐림 = 고켈빈 블루.
- 효율 기본값은 **HDRI + 보조광**(lookdev.json 의 hdri_plus_kicker): HDRI 가 환경·반사를, 그림자 쪽 면광 하나가 비율과 **접지 그림자**를 맡는다. HDRI 단독 그림자는 접지가 약하다 — 접지는 실광이 만든다.
- 키·필의 색온도가 1000K 이상 다르면 그것은 선언된 웜/쿨 의도여야 한다. 우연히 섞인 백색점은 티가 난다.

## 카메라 문법

| 용도 | 관례 | 이유 |
|---|---|---|
| 제품 팩샷 | 85–100mm 상당(FOV 20–30°), 3/4 뷰 | 50mm 미만은 광각 왜곡 |
| 히어로 소품 | FOV 20–30° + 로우 앵글 | 반직교의 기념비적 읽기 |
| 마크로 디테일 | 100mm 상당 | 각인·보석 |
| 환경·익스테리어 | 35mm, 높이 2m, 하향 15° | 마스터플랜은 24mm |
| 인테리어 | FOV 45–60° | |

- three.js 기본(FOV 50°, 눈높이, 정중앙)은 **미결정**이다. 3/4 뷰는 정면 대비 관찰 지표가 +27% — 데드센터 정면·수평선 정중앙은 선택일 때만 쓴다.
- 프리미엄·히어로 샷은 네거티브 스페이스 60% 이상. 화면 값 배분은 2/3 어둠 : 1/3 밝음(또는 역).
- 포트폴리오는 스틸 몇 장이 기본이고, 모션이 실제로 파는 것이 있을 때만 영상을 만든다.

## 접지와 무대

- **접촉 그림자가 접지 신호 1순위다.** 섀도 캐처 바닥 + 부드러운 면광 키 + 틈새 AO. 사이클로라마(섀도 캐처 무한 배경)가 수평선 없는 스튜디오 바닥의 표준 구현이다.
- 바닥 반사는 절제한다 — 러프니스 0 풀 강도 거울 바닥은 초보 티다.
- 스케일 단서를 심는다: 정확한 치수 + 익숙한 참조물. 유리·투명 재질은 브라이트 필드(흰 배경 + 검은 엣지 카드), 블랙 온 블랙은 다크 필드(배면 스트립 림) — lookdev.json 의 리그 그대로.

## 톤과 포스트

- 실시간 기본은 **AgX**(three r160+; ACESFilmic·Neutral 대안), 교환·합성은 ACES. 톤 변환 없는 선형 출력은 금지다.
- AgX 는 하이라이트를 희게 탈포화한다 — 기본값이 밋밋하면 변환 뒤에 채도를 그레이딩으로 되찾는다(raw 워크플로). 변환 앞에서 채도를 밀지 않는다.
- 블룸 임계는 1.0 — HDR 에서 1.0 을 넘는 픽셀(이미시브·스펙큘러)만 빛나야 한다. 임계를 내려 억지로 보이게 한 블룸이 아마추어 헤일로다.
- 포스트(DOF·비네트·그레인)는 깨끗하게 노출된 베이스에 하나씩, 절제해서. **조명 결함을 포스트로 가리는 것 자체가 지명된 초보 패턴이다** — 조명을 먼저 고친다.

## 턴테이블과 검증 트리오

- 표준 규격: **288 프레임 / 24fps / 12초 per 360°**, 등속, 첫 키프레임 복제 후 마지막 프레임 제거로 이음매 없는 루프. 8초/회전보다 빠르면 조급하다.
- 룩뎁 턴테이블에는 **18% 그레이 구·크롬 구·맥베스 차트**를 함께 돌린다: 그레이 구 = 노출, 크롬 구 = 환경 방향, 맥베스 = 색 파이프라인 검증.
- 노출 매칭이 필요하면 EV100 = log2(조리개² / 셔터 × 100/ISO) 로 렌더와 카메라를 같은 EV 에 놓는다.

## 데모 뷰어에 사상하기

lookdev.json 의 리그는 three.js 로 직역된다: 면광 = `RectAreaLight`(또는 크게 잡은 `DirectionalLight` + 부드러운 그림자 반경), 환경 = HDRI `PMREMGenerator` 또는 `RoomEnvironment`, 섀도 캐처 = `ShadowMaterial` 바닥, 톤 = `renderer.toneMapping = THREE.AgXToneMapping`. 리그의 방위각은 카메라 축 기준이므로 카메라를 먼저 앉히고 조명을 건다. 완성 확인은 look-floor.md 의 검증 항목으로 — 렌더를 열어서.
