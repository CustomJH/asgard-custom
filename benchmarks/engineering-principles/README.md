# 엔지니어링 원칙 배터리 — 2026-08-19 실측

"아스가르드가 소프트웨어 엔지니어링 원칙에 입각해 코드를 쓰는가"라는 물음을 반증 가능한 형태로
바꿔 놓았다. 널리 쓰이는 코드 리뷰 축에서 반례를 하나씩 만들어 실제 게이트(`asgard craft`,
`asgard thor gate`)에 통과시키고, 어느 것이 막히고 어느 것이 조용히 지나가는지 센다.

```bash
uv run --no-project python benchmarks/engineering-principles/run.py
uv run --no-project python benchmarks/engineering-principles/run.py --json
```

종료 코드는 덮인 비율이 아니라 **계기의 건강**으로 낸다. 양성 대조가 안 잡히면 1, 아니면 0이다.
못 덮은 원칙은 이 배터리가 보고할 사실이지 실패가 아니다 — 실패로 세면 구멍을 지우는 쪽으로
손이 간다.

## 이번 실행이 바꾼 것

첫 실행은 **7/19**였고 양성 대조 둘이 안 잡혔다. 그 둘을 파고든 결과가 갈렸다.

**하나는 규칙의 결함이었다.** `sql-interpolated`는 `WHERE name = %s`를 막으면서
`WHERE name = '%s'`, `WHERE a = '{}'`, `LIKE '%…%'` 셋은 알림으로 내려보내고 있었다. 값 자리
판정이 비교 연산자 **바로 뒤**만 값으로 읽어서, 연산자와 구멍 사이에 따옴표가 하나 끼면 식별자
자리로 분류됐기 때문이다. 따옴표를 손으로 넣었다는 것이 곧 문자열을 조립하고 있다는 증거라
오히려 더 위험한데, 가장 흔한 주입 형상이 통째로 새고 있었다. `_VALUE_SLOT`을 따옴표와 퍼센트
너머까지 넓혔고 코퍼스에 표본 넷(진양성 3 · 인용된 식별자 음성 1)을 박았다.

**하나는 표본의 결함이었다.** `quadratic-scan`은 훑는 대상이 **지역에서 만든** 시퀀스일 때만
잡는다 — 매개변수는 타입을 모르므로 set이 올 수도 있고, 걸면 올바른 코드를 막는다. 규칙이 일부러
안 잡는 자리라, 표본을 지역 리스트 형상으로 고치고 매개변수 형상은 `quadratic-scan-on-a-parameter`
라는 이름의 **문서화된 미검출**로 남겼다.

여기에 새 규칙 `unit-branchy`를 더해 지금은 **10/20**이다.

## 새로 덮은 것 — `unit-branchy`

길이와 중첩을 둘 다 지키면서 갈래만 스무 개인 함수는 두 예산이 못 본다. 한 단 깊이의 짧은 `if`
열여덟 개는 70행도, 중첩 4단도 안 넘는다. 결정점(순환복잡도 − 1)을 세어 15를 넘고 **이번 변경이
더 나쁘게 만든** 단위만 막는다 — 다른 craft 규칙과 같은 래칫이다.

문턱 15의 근거는 둘이다. McCabe의 원 권고는 순환복잡도 10이고 흔한 린터 기본값은 10~15라,
결정점 15(순환복잡도 16)는 그 관례보다 한 칸 느슨하다. 그리고 이 저장소 함수 4,874개 중
95.1%가 그 아래에 있다. 갈래는 자기 스코프 것만 센다 — 중첩 헬퍼의 갈래까지 합치면 쪼갠 사람이
벌을 받는다(코퍼스의 음성 대조군이 첫 구현에서 이 실수를 잡았다).

## 안 덮은 것과 그 이유

지어낸 규칙을 더하지 않기로 한 자리다. `craft_rules`의 계약이 "못 보는 것을 못 본다고 말하는
쪽이, 애매한 것을 걸어 신뢰를 잃는 쪽보다 낫다"이고, 판정기가 오탐을 내기 시작하면 다음에
일어나는 일은 사람이 판정기를 끈다는 것이다.

| 원칙 | 안 만든 이유 (실측) |
| --- | --- |
| 죽은 코드 | 파일 단위로 재면 이 저장소에서 198건이 뜨는데, 파이썬은 다른 모듈에서 `_이름`을 임포트할 수 있어 대부분이 오탐이다. 저장소 전체 참조 그래프가 있어야 하고 craft는 파일 단위다 |
| 중복 | 이 저장소의 실제 중복 사고는 **파일을 건너뛴** 것이었다(훅 라이브러리 사본 49개 중 9개가 갈라짐, 26-08-06). 파일 안만 보는 규칙은 그것을 못 잡는다. 6줄 창으로 세면 147곳이 뜨는데 겹치는 창과 인자 목록이 대부분이라, 문장 정규화와 저장소 범위가 먼저 필요하다 |
| 인터페이스 폭 | 매개변수 분포의 꼬리가 이 저장소에서는 **의도된 것**이다 — `root.py:tutor` 27개, `entry.py:run_tutor` 26개는 CLI 명령이고 매개변수 하나가 곧 플래그 하나다. 규칙을 걸면 옳은 형상부터 걸린다 |
| 문서화 | 결정론이긴 한데 이 저장소에서 "공개"의 경계가 흐리다(모듈 `_` 관례·dataclass·typer 명령). 경계를 세우기 전에는 오탐이 앞선다 |
| 무시된 반환값 · N+1 · 검증 없는 입력 · 동시성 | 타입이나 프로그램 전체 정보가 있어야 한다. 파일 하나의 AST로는 `session.fetch_author`가 I/O 인지, `requested`가 신뢰 경계 밖에서 왔는지 알 수 없다 |
| 이름 | `i`·`n`·`f`는 관용이고 좋은 이름은 문맥이 정한다. 길이로 재면 소음이 된다 |

## 이 배터리가 못 재는 것

게이트가 판정하지 않는 축은 여기 없다 — 설계 대안 중 무엇을 골랐는지, 요구사항을 바르게
읽었는지, 추상화의 경계가 옳은지. 그 판단은 Verifier와 사람의 몫이다. 재현율 숫자도 위로
편향된다: 표본을 사람이 썼고 규칙을 아는 사람이 썼다. 이 파일이 지키는 것은 **복귀 방지**와
**구멍의 이름**이지 판정기의 정밀도가 아니다.
