# 회수 지연 — k6 부하 시험

`benchmarks/longmemeval/REPORT.md` 는 품질을 행별 결과로 증명하지만 **지연은 증명하지
못했다**. 같은 결과가 416s 로도 149.2s 로도 적혀 있었고, "p50 9.5ms" 는 어느 코퍼스에서
어떤 부하로 잰 값인지 기록이 없었다. 여기가 그 자리를 메운다.

측정 대상은 `asgard memory dashboard` 가 실제로 내보내는 `/api/search` 핸들러다 —
벤치 전용 shim 이 아니다. shim 의 지연은 shim 의 성질이지 제품의 성질이 아니다.

## 실행

```bash
# 1) 대상 서버 (프로파일·리랭크를 골라 띄운다)
.venv/bin/python benchmarks/latency/server.py --profile short --port 8791
.venv/bin/python benchmarks/latency/server.py --profile long  --port 8792
.venv/bin/python benchmarks/latency/server.py --profile long --rerank off --port 8793

# 2) 부하 (단독 20s → 동시 8VU 40s)
asgard k6 run search --target http://127.0.0.1:8791 --env PROFILE=short --runner native
```

부하 형상은 `asgard-k6` 레인이 소유한다 (`search` 시나리오). 여기 있던 `load.js` 는 그쪽으로
옮겼다 — 스크립트가 세 벌로 갈라져 있는 동안은 어느 요약이 어느 규약으로 나온 값인지
대조할 수 없었다. 레인의 하네스 자체가 정합한지는 `asgard k6 selftest` 가 판정한다.

프로파일은 두 가지를 갈라 잰다. `short` = 정상 개인 메모리(페이지 ~300자, 100장)로
리랭크 길이 게이트가 전부 걸러내는 상태. `long` = 대화 로그처럼 자란 페이지(~12000자,
100장)로 리랭크가 실제로 도는 상태. 코퍼스는 씨앗이 고정돼 있어 같은 인자면 같은 형상이다.

## 실측 (26-07-28 · Apple Silicon · 시맨틱 ON · 100페이지)

| 프로파일 | 단독 p50 | 단독 p95 | 동시 8VU p95 | 처리량 |
|---|---|---|---|---|
| short (정상 개인 메모리) | **9.2ms** | 10.1ms | 164.7ms | 68.8 req/s |
| long (대화 로그) 리랭크 ON | 249.9ms | 304.1ms | 1748.6ms | 4.3 req/s |
| long (대화 로그) 리랭크 OFF | 158.8ms | 175.0ms | 1196.7ms | 6.0 req/s |

실패 0건 · 빈 결과 0건 (양쪽 프로파일 모두).

## 읽는 법

1. **"정상 개인 메모리에서 리랭크 비용 0" 은 사실이다.** 단독 p50 9.2ms 로 보고서의
   9.5ms 주장이 재현된다. 길이 게이트가 리랭크를 아예 안 켜기 때문이다.
2. **다만 그 수치는 리랭크가 켜졌을 때를 말해 주지 않는다.** 게이트를 통과하는 긴 페이지
   에서는 단독 p50 이 249.9ms 이고, 같은 코퍼스에서 2단계만 끄면 158.8ms 다 —
   **리랭크가 +91ms(+57%)**, 처리량은 6.0 → 4.3 req/s(−28%). 품질 +1.8pp 의 값이다.
   무료가 아니라 **정상 코퍼스에서 안 켜질 뿐**이고, 둘은 다른 말이다.
3. **동시성은 이 서버의 약점이다.** 8VU 에서 p95 가 short 에서도 164.7ms 로 벌어진다.
   단일 프로세스 파이썬 `ThreadingHTTPServer` + GIL 이라 회수는 CPU 바운드로 직렬화된다.
   개인 메모리 대시보드는 사용자 한 명이 보는 창이므로 설계상 문제는 아니지만,
   **다중 사용자 표면에 이 핸들러를 그대로 얹으면 안 된다**는 뜻이다.

## 한계

- 한 기계·한 번의 측정이다. 절대값은 기계마다 다르다. 비교해야 할 것은 **행 사이의 비율**
  (short↔long, ON↔OFF)이지 절대 밀리초가 아니다.
- 합성 코퍼스는 형상만 실물을 닮았다. 실제 개인 메모리의 낱말 분포와는 다르다.
- 100 페이지 기준이다. 인덱스가 훨씬 커지면 다시 재야 한다.
