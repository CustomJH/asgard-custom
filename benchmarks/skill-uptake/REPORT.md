# 스킬 도달 실측 — 배차가 새 스킬에 닿는가 (2026-08-13)

`asgard skills list` 에 이름이 뜬다는 것과 진짜 요청에서 그 스킬이 **불린다**는 것은 다른 일이다.
후자는 아무도 안 재 왔고 실패가 조용하다 — 트리거가 안 걸리면 스킬은 존재한 채로 한 번도 안 뜬다.
이 하네스가 후자를 잰다. LLM 없이 결정론으로만 돈다.

## 결과

값은 하나만 싣는다 — 지금 트리에서 `harness.py` 가 내는 것. 퀘스트 도중 판정이 구멍을 짚을
때마다 배터리가 자라서, 초기에 잰 "고치기 전" 숫자는 그때의 더 작은 배터리 값이고 오늘 명령으로
재현되지 않는다. 재현 안 되는 수를 표에 두면 다음 사람이 그것을 기준선으로 쓴다. 무엇이 어떻게
바뀌었는지는 아래 산문이 진다.

사례 건수는 여기 안 적는다. 배터리가 판정마다 자랐고, 손으로 옮겨 적은 건수가 이 퀘스트에서 네
번 어긋났다. 하네스가 매번 머리줄에 찍으니 그것을 봐라.

| 축 | 지금 | 뜻 |
|---|---|---|
| reach | **100%** (ko 100% · en 100%) | 트리거 낱말이 있는 요청에서 기대 스킬이 해석 결과에 나온 비율 |
| precision | **100%** | 관계없는 요청에서 새 스킬이 뜨지 않은 비율 |
| shape | **100%** | 형상 노트가 사용자 호출 오케스트레이터 이름을 대 준 비율 |
| shape-prec | **100%** | 한 조각짜리 요청이 `feature` 로 안 올라간 비율 |
| shape-rec | **100%** | 신설 표면 요청이 `feature` 로 올라간 비율 |
| semantic | 0% | 트리거 낱말이 하나도 없는 요청 — 하한이 아니라 결정론 층의 천장 |
| latency | 하한 아래 | `resolve_skills` 한 번이 p50 120ms 를 안 넘는다. 표본은 기계마다 다르니 여기 안 적는다 |

턴당 상시 부하 — 그 역할에 열린 model 호출 스킬의 이름+설명 글자 수. 이번 세 스킬이 느는 몫을
따로 뗐다.

| 역할 | 카탈로그 | 이번에 느는 것 |
|---|---|---|
| worker | 6,150 | +319 |
| eitri | 934 | +319 |
| thor · freyja · mimir | 4,196 · 4,255 · 616 | +0 |

신설 셋 중 `escort` 하나만 model 호출이라 부하를 진다. `lost` 와 `inquiry` 는 사용자 호출이라
카탈로그에 안 실리고 턴당 0을 낸다 — 그래서 셋을 얹고 늘어난 것이 319자뿐이다.

## 돌리는 법

```bash
uv run --no-project python benchmarks/skill-uptake/harness.py          # 표
uv run --no-project python benchmarks/skill-uptake/harness.py --json   # 기계용
uv run --no-project python benchmarks/skill-uptake/harness.py --check  # 하한 위반이면 exit 2
```

하한은 `reach · precision · shape · shape-prec · shape-rec 가 각각 1.0`, `latency p50 ≤ 120ms`. 회귀를
잡는 바닥이지 목표치가 아니다.

**reach 사례는 트리거 낱말을 품는다.** 배차가 부분 문자열 매칭이라 안 품으면 원리상 못 걸리고,
그래서 `reach 100%` 는 "의미를 알아본다"가 아니라 "그 낱말이 오딘이 실제로 칠 법한 문장 안에서
조사·굴절과 함께 있어도 걸린다"는 뜻이다. 그 이상으로 읽으면 안 된다. 자기 채점을 막는 것은
문장 쪽이 아니라 다른 두 축이다 — `deny` 사례가 트리거가 남의 요청까지 먹는지 보고,
`SEMANTIC_CASES` 가 낱말이 아예 없을 때의 천장을 따로 잰다.

한 사례는 이 변경 안에서 순환한다: `용어 정리부터 하자…` 는 같은 diff 가 `용어 정리` 를
트리거에 넣어서 통과한다. 나머지 18건은 이 퀘스트 이전부터 있던 트리거로 통과하므로 수치 자체는
살아 있고, 그 한 건은 아래 ①의 재고 고치는 고리에 해당한다. 이 diff 가 넣은 트리거 셋
(`glossary`·`용어 정리`·`용어 통일`)을 끄고 같은 24건을 돌리면 `reach 18/19`, 즉 딱 그 한 건만
빠진다 — 그것이 이 변경 이전의 배차다.

## 이 실측이 찾아낸 것

**① `domain-modeling` 이 "용어 정리"에 안 걸렸다.** 같은 개념을 두 자리가 따로 적고 있었다 —
`skill_scope._LENS_PAT["domain"]` 은 `용어\s*(?:정리|통일|정의)` 를 이미 갖고 있는데
`plugin.json` 의 트리거 목록엔 `도메인 용어` 밖에 없었다. 정본이 둘이면 한쪽만 자란다. 트리거에
`용어 정리`·`용어 통일`·`glossary` 를 얹어 맞췄다.

**② 한국어 신설 갈래는 넣었다가 지웠다.** 벤치가 처음 잡은 것은 `…화면을 새로 만들어줘` 가
`slice` 로 내려간다는 것이었다. 형상이 한 칸 내려가면 기능 규율도 `/blueprint` 제안도 통째로 안
뜬다. 그래서 `{표면}을 새로 {만들|추가|…}` 갈래를 넣었고, 판정 셋이 연속으로 같은 결함을 잡아
지웠다.

**결함은 하나다.** 신설을 **거절하는** 문장이 어간까지 글자가 같다 — `페이지를 새로 만들지 말고
기존 걸 고쳐줘`, `만들라고 한 적 없어`, `만들자는 게 아니라 고치자는 거야`. 거절 어형을 열거해도
샜고(조사 삽입·선행 부정·대체 표현이 각각 다른 방향으로 는다), 뒤집어서 요청 어미를 요구해도
샜다 — `자`·`야`·`라` 가 요청 전용이 아니라 내포절의 첫 글자이기도 하다. 요청인지 거절인지는
어간 뒤 두세 어절에서 갈리는데 이 층은 한 글자를 본다.

**지운 근거는 값이다.** 갈래 밖에서 온 지지 사례는 `결제 정산 화면을 새로 만들어줘` 하나였다.
나머지 다섯은 갈래를 지키려고 같은 퀘스트가 배터리에 넣은 문장이라 근거가 아니다. 반대편에서
확인된 회귀는 판정 셋에서 19건이고, 판정자가 새 문장을 지을 때마다 더 나왔다. Lagom 사다리의 첫
칸은 "필요한가"이고, Canon 9 는 같은 가설로 세 번 실패하면 틀린 것은 실행이 아니라 가설이라고
한다. 지운 지금 한국어 쪽은 퀘스트 이전과 정확히 일치한다 — 회귀 0, 과승격 0.

**여덟 번째 규칙을 여기서 소진시킨다.** 가장 그럴듯한 다음 수는 어휘가 아니라 위치다: `줘`·
`주세요` 처럼 부탁 전용 어미는 그대로 받고, `자`·`야`·`라` 는 **종결 위치에서만** 받는 것. 돌려
봤다. 비요청문은 다 떨어지지만 뒤에 절이 붙는 진짜 요청(`페이지를 새로 만들자 그리고 배포도
해줘`)이 함께 떨어져, 이번엔 미탐 쪽으로 같은 일이 난다. 여기서 멈춰라.

**메타 규칙 하나.** 자기가 쓴 배터리 위에 선 하한 1.0 은 규칙이 아니라 배터리를 잰다. 이 퀘스트
내내 `--check` 는 초록이었고, 구멍은 판정자가 **새 문장을 지을 때마다** 나왔다. 그래서 남은 구멍은
산문이 아니라 `shape-gap` 축이 진다 — 이 층이 못 잡는 신설 요청을 매 실행이 문장째로 찍는다.

영어 갈래도 같은 자리에서 네 번 틀렸다. `new` 와 표면 명사 사이 수식어를 허용하면 형용사 용법이
올라가고, 그래서 생성 동사를 요구하면 동사 없이 부탁하는 말이 내려가고, 복수형을 받으면 이미 있는
여러 개를 가리키는 문장이 올라가고, 정관사를 받으면 유지보수 요청이 올라간다. 지금은 `new` 바로
뒤에 표면 명사가 붙으면 동사를 안 따지고, 사이에 수식어가 끼는 자리에서만 생성 동사를 요구하며,
표면 명사는 단수, 관사는 부정관사만 받는다. 양쪽 방향 문장이 `SHAPE_DENY` 와 `SHAPE_WANT` 에 박혀
있어 어느 쪽으로 튀든 `--check` 가 exit 2 를 낸다.

남는 것 하나: 수식어 없는 형용사 용법(`the new page is broken`, `roll back the new flow`)은 지금도
`feature` 로 올라간다 — 이 퀘스트 이전 패턴도 똑같이 올렸으므로 회귀가 아니라 원래 있던 자리다.

**③ 기능 형상이 오케스트레이터 이름을 안 댔다.** `expedition` 형상만 `/expedition` 을 지목하고,
`feature` 형상은 규율만 말하고 이름을 안 댔다. `/blueprint`·`/quests` 는 사용자 호출이라 모델이
못 부르는데 이름조차 안 나오면 오딘에게 닿을 길이 없다. 부르지 말고 **제안하라**는 문장으로
넣었다 — 산출물을 자율 턴이 임의로 낳는 건 여전히 범위 밖이다 (Canon 7).

## 이 벤치가 못 재는 것

- **활용 품질.** 스킬이 떴다는 것과 그 절차를 제대로 밟았다는 것은 다르다. 이 하네스는 발견만
  잰다. 절차 준수는 실모델 A/B 가 필요하고 여기 없다.
- **모델의 자율 선택.** semantic 0% 는 "그 요청에서 스킬이 안 뜬다"가 아니라 "결정론 층이 거기까진
  못 도와준다"는 뜻이다. 트리거 낱말이 없는 요청에서 모델은 카탈로그 **설명**을 읽고 스스로 고르며,
  그 경로는 결정론으로 못 잰다. 하네스는 대신 그 자리에서 모델이 실제로 읽는 설명 문장을 같이
  출력한다 — 사람이 보고 판단하라는 뜻이다.
- **호스트 차이.** 여기서 재는 것은 `resolve_skills` 와 `scope_note` 다. Claude Code·Cursor·Codex
  가 자기 어댑터 목록에서 고르는 단계는 각 호스트 안에서 일어나고 이 하네스 밖이다.
- **자기 퀘스트 이전 값.** 배터리가 이 퀘스트 도중 판정마다 자라서, 지금 명령으로는 그때의 수를
  못 낸다. 재현되는 대조는 하나뿐이다 — 이 변경이 넣은 트리거 셋(`glossary`·`용어 정리`·`용어
  통일`)을 끄고 같은 24건을 돌리면 `reach 18/19`. 다른 "이전 값"이 필요하면 그 커밋에서 하네스를
  돌려라. 손으로 적어 둔 수를 믿지 마라.
- **경계의 잔여.** 결정론 층은 "새로 만든 것"과 "최근에 생긴 것"을, 그리고 신설 요청과 신설
  거절을 못 가른다. 수식어 없는 형용사 용법 `the new page is broken` 은 지금도 `feature` 로
  오르고(퀘스트 이전과 같다), 한국어 `…화면을 새로 만들어줘` 는 `slice` 로 남는다. 후자의 크기는
  `shape-gap` 축이 매 실행 찍는다 — 산문이 아니라 명령이 진다.
- **부하의 단위.** 글자 수이지 토큰이 아니다. 한국어는 글자당 토큰이 영어보다 크므로 역할 간
  비교에는 쓰되 절대 토큰 예산으로는 쓰지 마라.
